## 1. 목표 (Why)

- 이슈 #17("Inline local graph on the top", 2026-09-22, 사용자 Zazulias)에서 그래프를 노트 **상단**에 표시하는 옵션을 요청했다. 현재는 하단 표시만 가능하다.
- 설정에서 그래프 위치(상단/하단)를 고를 수 있게 한다. 기본값은 기존 동작(하단)을 유지한다.
- 과제: 기존에 상단에 두지 않았던 이유는 Edit 모드일때는 본문과 InlineLocalGraph 표시영역 사이에 넓은 공백이 생겨서 그걸 줄일 수 가 없었는데, 이 공백을 자연스러운 사이즈로 줄이기. 

## 2. 작업 범위 (Scope)

- 설정 항목 추가: 그래프 표시 위치 (`bottom` | `top`), 기본값 `bottom`.
- `main.ts`의 `showInlineGraphInEditor()`가 설정에 따라 그래프 컨테이너를 노트 맨 위 또는 맨 아래에 배치한다. 읽기 모드와 편집(소스/라이브 프리뷰) 모드 모두 해당한다. 구체적인 삽입 지점은 PLAN 1장의 측정 결과로 정한다.
- 편집 모드에서 본문과 그래프 사이의 넓은 공백을 자연스러운 간격으로 줄인다 (1장 과제).
- 설정 탭에 위치 선택 드롭다운과 i18n 문구(en/ko/ja) 추가.
- 설정을 바꾸면 이미 열린 노트의 그래프가 새 위치로 옮겨진다 (`updateGraphs()` 경로).
- `README.md` 설정 설명 갱신, 번역본 `README.ko.md`·`README.ja.md` 동반 수정 (PROJECT.md 규칙).
- `CHANGELOG.md`에 미배포(Unreleased) 항목 추가. 버전 bump·태그·릴리즈·PR·이슈 코멘트는 사용자 확인 후 별도 지시로 진행한다.

### 비범위 (Out of Scope)

- 노트 상단/하단 외의 위치(사이드바, 플로팅 등).
- 그래프 렌더링, 노드·링크 동작, 컨트롤 바 변경.
- 노트별 위치 지정(프론트매터 등). 전역 설정만 다룬다.
- 이슈 #9(README 갱신), `getSettingDefinitions()` 전환.
- 읽기 모드 긴 노트에서 하단 그래프가 문서 끝이 아니라 "현재 렌더링된 섹션 끝"에 붙는 기존 문제 (PLAN 1.3에서 발견). 기록만 하고 고치지 않는다.
- `test-vault/.obsidian/community-plugins.json`의 기존 로컬 수정 (이 태스크와 무관, 커밋하지 않는다).

## 3. 요구사항 / 수용 기준 (Acceptance Criteria)

- 설정 탭에 "그래프 위치" 드롭다운(상단/하단)이 있고, en/ko/ja 문구가 있다.
- 기본값은 하단이며, 기존 사용자의 저장된 설정(`data.json`)에 새 키가 없어도 하단으로 동작한다.
- 위치를 상단으로 바꾸면 읽기 모드와 편집 모드 모두에서 그래프가 노트 제목·본문보다 위에 표시된다.
- 편집 모드에서 그래프와 본문 사이 간격이 그래프 컨테이너 여백(2em) 수준이다. 하단 배치 기준 수정 전 약 400~500px(창 높이의 절반 + 2em)인 공백이 없어진다.
- 위치 설정을 바꾸면 노트를 다시 열지 않아도 반영된다.
- 노트 전환, 모드 전환, 그래프 토글 명령에서 컨테이너가 중복 생성되지 않는다.
- 읽기 모드 상단 배치에서 긴 노트를 스크롤해도 본문이 빈 화면으로 남지 않고 그래프가 맨 위에 유지된다.
- `npm run build`가 오류 없이 끝난다. `npm run lint`에서 새 위반이 없다.
- `test-vault`에서 상단/하단 각각 동작 확인 (사용자 수동 확인).

## 4. 영향 범위 / 고려사항

- 편집 모드 하단 배치에서 공백을 없애면, 그래프가 있을 때는 CodeMirror의 "끝 너머 스크롤(scroll past end)" 여백이 사라진다. 그래프가 노트의 마지막 요소이므로 끝까지 스크롤하면 그래프 하단이 화면 하단에 맞춰진다.
- 읽기 모드는 Obsidian이 섹션 단위로 가상 렌더링한다. 제목·속성 헤더(`.mod-header`)도 가상화 대상이라 그 주변에 넣은 요소는 위치가 보장되지 않는다 (PLAN 1.3).
- MutationObserver(`main.ts:57-61`)가 DOM 삽입에 반응하므로 삽입 위치 변경이 재렌더 루프를 만들지 않는지 확인해야 한다.
- 설정 키 추가는 `DEFAULT_SETTINGS` 병합으로 하위 호환이 유지된다.
